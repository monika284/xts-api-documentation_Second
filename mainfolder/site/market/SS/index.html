Socket Streaming

Socket Streaming creates a live connection between your application and the Market Data server. Once connected, market updates are automatically pushed in real time — no repeated requests needed.

Real-time updates
Low latency
No repeated calls
WebSocket based
Live price & depth
Efficient bandwidth

How Socket Streaming Works

Connect
→
Subscribe
→
Receive Updates
→
Unsubscribe
→
Disconnect
1. Connect

Establish a WebSocket connection with the Market Data server using your authentication token.

2. Subscribe

Subscribe to instruments using Exchange Segment and Exchange Instrument ID. Server starts tracking them.

3. Receive Updates

Server automatically pushes data whenever market changes occur. No additional requests needed.

4. Unsubscribe

Stop receiving updates for specific instruments at any time without closing the connection.

5. Disconnect

Close the WebSocket connection when streaming is no longer required.

Socket Events

Event Description
joined - Socket connection established successfully.
- Fired when the client connects to the WebSocket server.
success - A request or operation completed successfully.
- Returned after a valid subscribe or unsubscribe action.
warning - A non-critical issue that may require attention.
- Does not stop the connection but should be noted.
error - An operation failed or could not be completed.
- Check the error message for details and retry if needed.
trade - Sent when a trade is executed in the market.
- Contains trade price, quantity, and time details.
order - Sent when an order-related update is available.
- Includes status changes like filled, partial fill, or cancelled.
position - Sent when there is a change in positions or holdings.
- Helps track live portfolio changes in real time.
logout - User has been disconnected from the socket session.
- Reconnection may be required after this event.
tradeConversion - Sent when a position is converted from one product type to another.
- Example: MIS to NRML or CNC conversion.
getOrder - Returns details of existing orders.
- Use to fetch current order status and information.
getOrderRejection - Returns information about rejected orders.
- Includes the rejection reason for debugging and user notification.

Example Workflow

// Step 1 — Login & get token
token = "eyJhbGci..."

// Step 2 — Connect to WebSocket
connect("wss://marketdata.server", token)

// Step 3 — Subscribe to instruments
subscribe(["NSECM:2885", "NSECM:11536"])  // RELIANCE, TCS

// Step 4 — Server pushes live updates automatically
onData(event → process price update)

// Step 5 — Unsubscribe RELIANCE
unsubscribe(["NSECM:2885"])

// Step 6 — Disconnect
disconnect()

Introduction

To receive streaming Market Data events, you must use the Socket.IO library. For more information, visit: https://socket.io/.

Real-Time Streaming Flow

Once the connection is established, real-time streaming data can be obtained by listening to the socket on the relevant market data ports. The streaming data will be received on these ports, and upon receiving the data, you are free to process it as required.

Below are the steps to follow to correctly implement the real-time streaming flow:

  1. Establish the socket connection
  2. Listen to real-time streaming events

Establishment of Socket Connection

You can connect to the server by sending the userID, token, source, and broadcastMode as query parameters. The token is available only after a successful RESTful login request, as described in the RESTful section of the documentation.

import socketio

# Base URL of the ApiMarketdata API server
url = "https://xts.rmoneyindia.co.in:3000"

# Required credentials
userID = ""
token = ""

broadcastMode = "Full" # "Partial"
publishFormat = "JSON"
socketio_path = "/apibinarymarketdata/socketio"
logger = False # True

# Create Socket.IO client
sio = socketio.Client()

connectionString = f"{url}?token={token}&userID={userID}&publishFormat={publishFormat}&broadcastMode={broadcastMode}"

@sio.on("connect")
def connect():
    print("Connection Established")

@sio.on("disconnect")
def disconnect():
    print("Disconnected")

@sio.on("joined")
def joined(data):
    print("Socket Joined", data)

@sio.on("error")
def error(data):
    print("Error", data)

Listening to Real-Time Streaming

Once the socket connection is successfully established, you can listen to real-time streaming data by subscribing to the attached market data ports. The complete market data will be received as a string.

Connect

The user needs to connect to the server via a socket (i.e., WebSocket). It is important to set the path parameter value as /socket.io during the connection. The token will only be available after a successful login, so make sure you log in first before connecting to the server via socket.

Here, the URL is the REST API address used to connect to the interactive server (e.g., www.test.example.com). Once connected to the server, you can listen to the following events: SocketEvents. An example of a connect event is given below

@sio.on("connect")
def connect():
    print("Connection Established")

Joined

If a successful connection is established with the server, this event will be raised to indicate that the user has been connected.

@sio.on("joined")
def on_joined(data):
    print("Socket Joined", data)

Error

In case of any error with the server, this event will be raised along with the cause of the error. For example, if you send an incorrect token while connecting, the server will raise this event and disconnect your socket connection.

@sio.on("error")
def on_error(data):
    print("Error", data)

Disconnect

In case a socket disconnection occurs with the server, this event will be raised to indicate the disconnection.

@sio.on("disconnect")
def on_disconnect():
    print("Disconnected")

Binary Marketdata Event

BinaryData
Binary data event

@sio.on("xts-binary-packet")
def on_binary_full(data):
    print("Binary data Full:", data)

Note

  • If the packet is compressed, decompress it using zlib, and then deserialize the final packet.
  • If the packet is not compressed, you can directly deserialize the packet.
  • The isGzipCompressed flag is present in the parent header of the received packet. The final packet must be iterated accordingly.
  • Further deserialization should be performed based on the message code.
